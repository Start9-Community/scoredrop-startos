# Scoredrop on StartOS

> Everything not listed in this document should behave the same as upstream
> Scoredrop. If a feature, setting, or behavior is not mentioned here, the
> upstream documentation is accurate and fully applicable — see the
> Documentation section of `instructions.md` for links.

[Scoredrop](https://github.com/martinbarilik/scoredrop) is a self-hosted sport
event notifier: it polls public fixture sources for the teams you subscribe to
and pushes match notifications to an ntfy server.

## Image and Container Runtime

The package runs the upstream image unmodified, with the image's own entrypoint.

| Property      | Value                                                       |
| ------------- | ----------------------------------------------------------- |
| Image         | `martinbarilik/scoredrop` (Docker Hub), upstream unmodified |
| Architectures | x86_64, aarch64                                             |
| Entrypoint    | Upstream `bin/docker-entrypoint`, then Thruster + Puma      |

One subcontainer, `main`. A `chown` oneshot first hands the `main` volume to
uid 1000, the user the image runs as. The entrypoint then starts an embedded
PostgreSQL bound to `127.0.0.1`, runs database migrations, and starts Thruster
on port 8080 in front of Puma on port 3000. The background poller is a thread
inside the Puma process.

The package sets these environment variables:

| Variable           | Value     | Why                                                                     |
| ------------------ | --------- | ----------------------------------------------------------------------- |
| `HTTP_PORT`        | `8080`    | The image runs as uid 1000 and cannot bind upstream's default port 80.  |
| `LANG`, `LC_ALL`   | `C.UTF-8` | The image ships only C/POSIX locales; any other locale breaks `initdb`. |
| `SCOREDROP_CONFIG` | empty     | Disables upstream's seeded example config (see First-Run Flow).         |

## Volume and Data Layout

Everything lives on the single `main` volume, mounted at `/data`.

| Path                    | Contents                                                             |
| ----------------------- | -------------------------------------------------------------------- |
| `/data/postgres`        | Embedded PostgreSQL data directory: settings, subscriptions, matches |
| `/data/secret_key_base` | Rails secret, generated by the entrypoint on first boot              |
| `/data/store.json`      | StartOS-side state: the web interface password                       |

## File Models

The package owns one file, `store.json` on the `main` volume. It holds
`uiPassword`, written only by the **Set Web Interface Password** action and read
by the interface binding, which re-reads it whenever it changes.

Scoredrop's own configuration lives in its database and is managed only from
its Settings page. The package writes no upstream configuration file.

## Dependencies

None. The ntfy server Scoredrop publishes to is entered in its Settings page and
can be any ntfy server, on this StartOS server or elsewhere.

## Network Access and Interfaces

The package exposes one interface.

| Id   | Type | Port | Protocol | Purpose                                |
| ---- | ---- | ---- | -------- | -------------------------------------- |
| `ui` | `ui` | 8080 | HTTP     | Scoredrop's web UI and `/up` endpoint. |

Every address of this interface, the plaintext bridge address included, is
gated by HTTP Basic authentication enforced by the StartOS reverse proxy
(username `admin`, realm `Scoredrop`). Upstream Scoredrop has no login of its
own.

## Installation and First-Run Flow

Setup differs from upstream in two ways.

1. **A password is required before first start.** Install raises a critical
   task for **Set Web Interface Password**; the service cannot start until it
   runs. The action returns the credential.
2. **No example configuration is imported.** The upstream image copies an
   example `config.yml` onto `/data` and imports it on first boot, which would
   subscribe to a team and publish to the public `ntfy.sh/scoredrop` topic. The
   package suppresses this, so a fresh install has no subscriptions and no ntfy
   server until the user sets them in the web UI.

## Actions

One action, user-facing.

**Set Web Interface Password** (`set-password`) — run it once to clear the
install task, and again whenever the password must change. It generates a
32-character password, stores it in `store.json`, and returns username and
password once. The proxy gate switches to the new password within seconds,
without restarting the service; the old one is rejected immediately. Running it
again always replaces the password, and its title reads **Reset Web Interface
Password** once one is set.

## Tasks

The package creates one task.

| Task                       | Severity | Raised when                        | Cleared by                             |
| -------------------------- | -------- | ---------------------------------- | -------------------------------------- |
| Set Web Interface Password | critical | `store.json` holds no `uiPassword` | Running **Set Web Interface Password** |

It is raised on every fresh install. A restore brings the password back with
the backup, so it is not raised again.

## Health Checks

One check, on the daemon.

| Check           | Probe                                                 | Failure means                                                                                                                                                                              |
| --------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Web Interface` | Port 8080 accepting connections, default grace period | Thruster is not up: the entrypoint is still initializing PostgreSQL or running migrations, or it exited. The first start takes a few seconds; a persistent failure is in the service logs. |

## Backups and Restore

The `main` volume is copied wholesale (`ofVolumes`), including the PostgreSQL
data directory, the Rails secret, and `store.json`. StartOS stops the service
for the backup, so PostgreSQL is shut down cleanly before its files are copied.

A restored instance needs nothing further: subscriptions, ntfy settings, match
history, and the web interface password all come back.

## Limitations and Differences

1. Upstream's first-boot `config.yml` import is disabled; configure everything
   through the web UI.
2. The web UI sits behind StartOS's HTTP Basic authentication; upstream has no
   login of its own.
3. Run one instance only: the embedded database and the in-process poller are
   single-process, and a second copy would send duplicate notifications.
4. Notifications can trail real time by a minute or two, because the upstream
   fixture APIs are edge-cached.

## Quick Reference for AI Consumers

```yaml
package_id: scoredrop
image: martinbarilik/scoredrop
architectures: [x86_64, aarch64]
subcontainers: [main]
volumes:
  main: /data
file_models:
  - /data/store.json
startos_managed_env_vars:
  - HTTP_PORT
  - LANG
  - LC_ALL
  - SCOREDROP_CONFIG
dependencies: none
interfaces:
  ui: { type: ui, port: 8080 }
actions:
  - set-password
tasks:
  - { action: set-password, severity: critical }
health_checks:
  - main
```
